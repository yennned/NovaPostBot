# 09 — Интеграция Нової Пошти

Модуль `app/novaposhta/`: `client` (транспорт/ретраи/классификация ошибок),
`methods` (типизированные обёртки над методами НП), `mapping` (**чистый** маппинг
домен → `methodProperties`, без сети), `schemas`, `cache` (Redis-кэш справочников),
`tracking`, `exceptions`. Ключ НП — у каждого ФОП клиента, зашифрован Fernet в
Postgres. Бот — единственный канал отправок.

Версия API — v2.0 (`https://api.novaposhta.ua/v2.0/json/`). НП **всегда отвечает
HTTP 200**, бизнес-сбой выражен `success=false` в теле — отсюда двухступенчатая
классификация в `client.py` (по HTTP-коду → по конверту `errorCodes`/тексту).
Ретраи навешены только на `NovaPoshtaUnavailable`; `success=false` не ретраится.

## Используемые методы

- **`InternetDocument.save`** — создание ТТН (NP-first: сначала save, потом
  `Shipment` + резерв).
- **`InternetDocument.delete`** — отмена ТТН (до `dispatched`).
- **`InternetDocument.getDocumentPrice`** — расчёт стоимости/срока (онлайн-
  ценообразование).
- **`TrackingDocument.getStatusDocuments`** — трекинг (батч до 100).
- **`Address.getCities` / `Address.getWarehouses`** — справочники городов/
  отделений (кэш в Redis с TTL).
- **`validate_key_and_get_sender`** — проверка ключа ФОП + подтягивание Ref
  контрагента/контакта при сохранении ФОП.

## Поля SenderProfile (ФОП) → отправитель ТТН

- `account_id` — бізнес-акаунт, которому принадлежит ФОП (legacy-колонка
  `client_id` осталась ради истории; скоуп идёт по `account_id`).
- `name` — назва ФОП (видна клиенту при выборе).
- `np_api_key` — ключ НП, **Fernet-шифр** (для вызовов API).
- `sender_full_name` — ПІБ отправителя (контрагент НП).
- `sender_phone` — телефон отправителя.
- `org_type` — ФОП / ТОВ.
- `edrpou` — ЄДРПОУ/ІПН (для ТОВ/ФОП по необходимости).
- `np_sender_ref` / `np_contact_ref` — Ref контрагента-отправителя в НП
  (кэшируются при валидации ключа).
- `np_sender_warehouse` — склад-отправитель НП (наш склад по умолчанию).
- `is_default` — ФОП по умолчанию (если один — авто-выбор).
- `created_at`, `updated_at`.

При сохранении ФОП: валидируем ключ, подтягиваем Ref'ы и реквизиты, кэшируем.
Ошибка ключа → ФОП не сохраняется.

## Поля оплаты/страховки → `InternetDocument.save` (решение F)

- `PayerType` = **Recipient** (по умолчанию) или **Sender** — выбор клиента на
  карточке ТТН. (Платник за доставку.)
- `PaymentMethod` = **Cash** — захардкожено, клиенту не показывается; на функции
  бота не влияет (меняется одной константой).
- `Cost` = **оцінкова (страхова) сума**, база страхового сбора. Клиент правит её
  на карточке; **если не трогал — уходит `0`**. Валидации «> 0 и ≥ минимума НП»
  сейчас нет (см. «Что не реализовано» в [ROADMAP.md](ROADMAP.md)).
- **Накладений платіж (COD)** — только если выбран клиентом:
  `AfterpaymentOnGoodsCost = <сума>` — услуга **«Контроль оплати» (NovaPay)** для
  ФОП/юр-особи; НП маршрутизирует по договору NovaPay, номер счёта в скалярной
  форме не нужен. Передоплата → поле не отправляется.
- **НЕ `BackwardDeliveryData{CargoType: 'Money'}`.** Это классическая Післяплата
  для фіз-осіб, на наших ФОП-ключах недоступна («Передана послуга Післяплата
  недоступна») — проверено боем. Два поля взаимоисключающие; запрет закреплён
  тестом (`assert "BackwardDeliveryData" not in props`). Причина и решение — в
  докстринге `app/novaposhta/mapping.py`.
- В **оценке** цены комиссия COD прикидывается через `RedeliveryCalculate`
  (`getDocumentPrice`) — это лишь ориентир НП; фактическую комиссию NovaPay
  подтверждает менеджер при отправлении.

## Получатель

- Тип: **фізособа** (PrivatePerson) / **юрособа** (Organization).
- Юр: назва ФОП/ТОВ + ЄДРПОУ при необходимости; контактна особа (ПІБ + телефон).
- Місто/відділення — из справочников НП по выбору клиента.

## Габариты и места (`OptionsSeat`)

`InternetDocument.save` отклоняет запрос, где заданы только `SeatsAmount`/`Weight`:
**`OptionsSeat` обязателен даже для одного места** (выяснено боем, не из
документации). Внутри `OptionsSeat` поля — **camelCase**, в отличие от PascalCase
остальных полей запроса:

```
OptionsSeat: [{ volumetricVolume, volumetricWidth, volumetricLength,
                volumetricHeight, weight }]
```

- Объём места = Д×Ш×В / 1 000 000 (м³). Габариты задаются все три или ни одного.
- Вес места = общий вес / число мест, квантование до 0.001 кг, **с нижней границей
  0.001** — иначе очень лёгкое место ушло бы нулём при непустом `Weight`, и НП
  отклонила бы ТТН.
- `VolumeGeneral` отправляется, только если объём задан явно; при обычном пути из
  бота (габариты пресета) в запрос не попадает.
- **Пресеты коробок** зашиты в боте (`app/bot/keyboards/ttn.py`): «Мала» 20×20×10,
  «Середня» 30×30×20, «Велика» 40×40×30 см; вес пресета подставляется
  автоматически (2 / 10 / 30 кг) и правится вручную. Габариты **не сохраняются в
  БД** — в `shipments.size_preset` лежит только текстовая метка, поэтому по базе
  нельзя восстановить, что именно ушло в НП по конкретной ТТН.

## Ценообразование (онлайн + локальный объёмный вес)

Тарифы, відстань місто↔відділення, страховой сбор от `Cost`, ориентир комиссии COD
и справочники відділень/міст **берутся из API НП онлайн** (`getDocumentPrice`,
`Address.*`) — бот не хранит «замороженных» тарифов. Справочники кэшируются в Redis
с TTL, оценка цены — в FSM-data по хэшу влияющих полей (ФОП, місто, вага, пресет,
страхова сума, COD); смена любого из них инвалидирует оценку, есть и кнопка
«🔄 Перерахувати ціну».

**Объёмный вес считается локально.** НП тарифицирует по максимуму из фактического
и объёмного веса, а `getDocumentPrice` мы зовём без габаритов, поэтому объёмный вес
воспроизводим по правилу НП сами: `объём(м³) × 250` (эквивалент Д×Ш×В см / 4000),
и отправляем `Weight = max(фактический, объёмный)`. Для «Великої» это 12 кг: клиент,
поставивший 2 кг вручную, видит цену за 12 — ровно ту, что посчитает НП по
`OptionsSeat` при создании ТТН. Когда объёмный вес перебивает фактический, карточка
показывает тарифную вагу отдельной строкой. Коэффициент — константа
`VOLUMETRIC_KG_PER_CUBIC_METER` в `mapping.py`.

**Отказ НП не блокирует оформление:** ошибка `getDocumentPrice` → «розрахунок
недоступний, вартість підтвердить менеджер». Ответ без поля `Cost` намеренно
возводится в ошибку — лучше «недоступно», чем «0 грн» за доставку.

## Расхождение веса при отправке

Декларируемый размер — оценка. При сдаче НП перевзешивает, **сама пересчитывает
стоимость и отправляет посылку** — без отмены/пересоздания и без беспокойства
клиента. Платит платник (по умолчанию получатель). Бот может тихо синхронизировать
факт. вес/стоимость в карточку ТТН для учёта (без сообщений клиенту).

## Надёжность

NP-first порядок (save → запись + резерв); ретраи к НП; транзакционность списания;
понятные ошибки клиенту при сбое (ничего не резервируем).
